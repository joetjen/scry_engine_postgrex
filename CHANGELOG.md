# Changelog

## [Unreleased]

### Fixed

- **`ORDER BY` pushdown regression from `scry_core`'s `Query.t().order_bys` widening**: `scry_core` widened `order_bys` from `[{[String.t(), ...], :asc | :desc}]` (a bare field path) to `[{expr(), :asc | :desc}]`, so a sort key can now be any expression (e.g. the upcoming `ORDER BY relevance()`, or `ORDER BY price * quantity`) -- a real parsed `ORDER BY age` now produces `{{:field, ["age"]}, :asc}`, not `{["age"], :asc}`. This `SqlCompiler`'s `order_by_item/2` only ever matched the old bare-list shape, so *every* `ORDER BY` query -- including the ordinary single-field case -- fell through to its catch-all and was rejected as `{:unsupported, {:order_by, _}}` once this package picked up the updated `scry_core`. `order_by_item/2` now also unwraps the common `{:field, [column]}` case back to the plain column the existing identifier check already validates, while still declining (correctly) any other expression shape -- a multi-segment field, a call, arithmetic -- since this compiler gains no general expression-compilation capability from this fix, only recognition of the one new common-case wrapper. The old bare-list shape (`{[column], direction}`) is still accepted too, for any caller still constructing a `%Scry.Core.Query{}` literal directly with it (matching `Scry.Core.QueryOps`'s own backward-compatible runtime resolution).

### Changed

- **Breaking (pre-release)**: renamed from `scry_engine_relational_postgrex` to `scry_engine_postgrex` (`Scry.Engine.Relational.Postgrex` → `Scry.Engine.Postgrex`) -- `impl_spec.md`'s own tier-3 adapter naming convention simplified to `scry_engine_<driver>` universally, dropping the `scry_engine_<kind>_<driver>` form entirely rather than keeping it as the default with a "kind-independent" exception (see `scry`'s own `CHANGELOG.md` for the full reasoning). This package was never released (no Hex publish, no git tag), so this is a same-round rename, not a deprecation.

### Added

- Initial implementation: `Scry.Engine.Postgrex`, a real `Scry.Core.EngineBehaviour` implementation over PostgreSQL via `postgrex` — the direct Postgres counterpart to `scry_engine_exqlite`, ported deliberately from that package (impl_spec.md §2/§6 names this exact package, `scry_engine_postgrex`, on the Day-One Engine Roadmap). `execute/3` compiles the entire flat query — `WHERE`/`GROUP BY`/aggregates (`sum`/`avg`/`count`/`min`/`max`/`count(distinct ...)`)/`ORDER BY`/`DISTINCT`/`LIMIT`/`OFFSET`/projection — into one native SQL statement, all or nothing, declining cleanly (`{:error, {:unsupported, detail}}`) rather than a partial pushdown finished off in Elixir. A nested/correlated `SELECT` or a `WITH`-bound source delegates whole to `Scry.Core.QueryOps.run_document/4`.
  New `Scry.Engine.Postgrex.Conn` (a `postgrex` connection pool wrapper, not a single raw handle like `scry_engine_exqlite.Conn` — a pool is, if anything, a more natural fit for "opened once, reused across every call" than a single SQLite file handle was), `Scry.Engine.Postgrex.WhereTranslator` (predicate-tree → SQL text, `?` placeholders later renumbered to Postgres's own `$1, $2, ...`), `Scry.Engine.Postgrex.SqlCompiler` (SELECT/WHERE/GROUP BY/aggregate rendering), `Scry.Engine.Postgrex.Schema` (`information_schema.columns`-based introspection, `verify/3`, `describe_source/2` — `Scry.Core.EngineBehaviour`'s optional callback, feeding `Scry.Core.TypeCheck.Introspection`).
  Real, deliberate differences from the SQLite port, confirmed empirically while building this package, not just designed: (1) Postgres's own strict, disambiguated column types make SQLite's whole `type_checks`/type-affinity-mismatch correctness class unnecessary — dropped entirely, not ported; a genuinely mismatched comparison is rejected by Postgres itself (`{:error, {:query_error, _}}`), never a crash or a silently wrong answer. (2) A boolean value and a `DateTime.t()`/`NaiveDateTime.t()` value both bind **directly** — Postgres has real native `boolean`/`timestamp`/`timestamptz` types, so neither of SQLite's own workarounds (refusing booleans outright, encoding a timestamp as an epoch-microseconds integer) is needed. (3) `avg`/`sum` over an `integer`/`bigint`/`numeric` column stay genuinely **exact** (Postgres's own `numeric` result, decoded by `postgrex` as `Decimal.t()`, converted to `Scry.Core.Rational`) — a real improvement over SQLite's `avg`, which is always an inexact float. (4) An ordering comparison (`<`/`>`/`<=`/`>=`) against a string value forces `COLLATE "C"` (byte-wise comparison) — found directly via property testing: Postgres's default collation is locale-aware, not byte-order, and can silently disagree with `Scry.Core.QueryOps.eval_predicate/4`'s own Erlang-term-order semantics otherwise. (5) Schema-cache freshness has no automatic re-check the way SQLite's cheap, global `PRAGMA schema_version` integer allows — `Schema`'s own cache, once populated, stays valid until explicitly busted (`Schema.invalidate/2`) or the pool restarts, a real, accepted, documented limitation. (6) Deliberately **eager, not lazy** this version — every query fully materializes its own rows before `execute/3` returns; genuine server-side-cursor streaming needs a connection checked out and a transaction held open across `execute/3`'s own return boundary, real, separate machinery not built yet.
  Ships a `docker-compose.yml` (a disposable local `postgres:16` service) and `test/support/test_conn.ex` — this package's own test suite requires a real, reachable Postgres (`docker compose up -d` before `mix test`/`mix precommit`, documented in README.md), the same "test against the real thing" philosophy `scry_engine_exqlite`'s own SQLite-file-per-test suite already has.
  Full test suite ported and extended from `scry_engine_exqlite`'s own: `conn_test.exs`, `where_translator_test.exs` (including the new `COLLATE "C"` and native-boolean/DateTime cases), `sql_compiler_property_test.exs` (an `Engine.execute/3` vs. `Scry.Core.QueryOps.run_flat/3` oracle, the direct replacement for the automatic re-verification the old, lenient `fetch/3`-era contract used to provide for free), `schema_test.exs` (including the new `invalidate/2`/stale-cache-limitation cases), `aggregate_test.exs` (including the new exact-`avg` cases, both whole and genuinely fractional), and `postgrex_test.exs` (plain pushdown, delegation to `run_document/4`, `describe_source/2`, end to end through `Scry.Core.Executor.run/4`).
